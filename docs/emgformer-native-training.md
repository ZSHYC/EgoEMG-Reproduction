# 原生 EMGFormer 训练入口与中心验证

新的 S/M/L 训练入口保留原生 200 轮上限、batch 500、六 worker、BF16、seed 42、AdamW 5e-5、cosine T_max 200 / eta_min 1e-5、有效指尖损失 0.02 及全部原回调。ModelCheckpoint 按 val_mae/min 保留 top3/last；EarlyStopping 保持 patience 200。完整有限训练必须实际完成 200 轮，短程检查不能被标记为完整训练。

训练读取完整22×12000目标，验证保持22×1中心目标和长度1的原标签掩码。观察器在同一次原生模型前向中取得实际完整预测，核对 Lightning 返回的预测确实是原输出的中心切片，目标和掩码与原批次精确相同；不重跑模型前向，不重新对齐上下文。此前融合初始化的150轮/batch260/零worker/完整验证轨迹/0.01属于另一实验。

[服务器实际 CPU 证据](../results/native-emgformer-train-cpu-20261029.json)绑定源码 `8498910`：前缀32.762秒实际2更新，新进程续训33.367秒再2更新，第三进程2.730秒独立重开原始检查点、没有构造模型或执行更新。三个阶段均实际退出0，八个记录的拥有进程均退出，98个冻结成员及16个合成输入文件的九项属性未变。前两阶段各构造一个原生Small模型，实际参数3,460,134；真实数据训练和GPU资格尚未获得。

短程检查明确使用合成数据、CPU FP32、batch2、零worker、最多两轮。训练每轮选择原数据索引0、1、170、171，覆盖左右各两个样本；验证使用全部四个手样本。模型、优化器、调度器、回调、循环和父进程随机状态六个保存状态域在原生恢复完成时精确一致，续训前完整冻结验证也一致。所有原生回调和cosine200参数保留，按验证成绩选优，拒绝把工程结果重标为完整训练。父进程状态恢复不承诺 persistent-worker 后续随机训练轨迹逐位一致。

本机18项新训练入口检查通过，90.70秒；另有14项上游弃用警告。检查覆盖三种规模配方、实际双手训练/中心验证/恢复、原始best选择、检查点与覆盖修改拒绝、完成后拒绝重训，以及结果记录落后时从已完成检查点恢复且不增加更新。本机Python3.12/Torch2.2.2+cpu与服务器Python3.11/Torch2.2.2+cu118分别执行一次四更新集成；服务器环境另用检查点读者验证，不把两环境的随机训练轨迹当作逐位相同。日志依赖使用已有目录，未更换官方TensorBoardLogger或安装新包。
