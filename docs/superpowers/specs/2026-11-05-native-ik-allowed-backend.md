# Native IK continuation on a newly qualified allowed GPU

The user prohibits physical GPUs0/1. This operational amendment implements that
explicit restriction inside the approved whole-paper reproduction. It introduces
no new model, optimizer, data reduction or scientific protocol. Existing inline
execution continues; the executor chooses the resource binding described here.

## Requirements

1. Reject every new CUDA request targeting either protected UUID or any device
   outside the actual physical2–7/knownUUID mapping, including engineering CUDA.
   A logical `cuda:0` must map to its explicitly allowed physical UUID. Check the
   real NVML index before execution and throughout resource waits/consumption.
2. Preserve the original13-file scientific snapshot and the four numerical core
   files byte-for-byte. Keep the original68 packets, incomplete next batch, actor
   identities, old configuration and old GPU1 qualification read-only. Historical
   qualification reading allocates no CUDA and does not authorize new work.

   `_check_qualification`. Bind the new physical descriptor, permit file hash and
   all raw/stage artifacts. Its actual scientific runtime identity must equal the
   old prefix runtime; no relabeling old permits or accepting engineering permits.
4. Only `gpu_uuid`, `qualification` and `minimum_free_bytes` may differ from the
   original full request. All scientific inputs, source/asset paths, engineering
   mode, device policy, batch10096 and original selector/optimizer remain exact.
   CPU engineering retains its old request except operational disk reserve.
5. Record old prefix hardware separately from current qualified hardware. Every
   fresh worker independently reopens the new qualification and compares the same

   guards retain them while waiting and at final publication.

## Choice

Use a new qualification on an allowed card and retain the historical prefix.
Using GPU1 violates the user instruction. Rebranding its permit would remove
physical backend evidence; discarding68 valid packets would repeat optimization
without resolving the resource restriction. No further design choice is needed
from the user for this operational amendment.

The change is confined to the continuation runner and focused boundary tests.
The original qualification CLI remains unchanged; a qualification-only waiting
capsule already exists with exact recorded handles. One fresh review covers this
new backend transfer boundary, without repeating old IK/model mathematics or the
closed prior mixed-lineage review.
