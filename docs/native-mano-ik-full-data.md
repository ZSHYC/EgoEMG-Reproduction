[执行计划](superpowers/plans/2026-11-01-native-mano-ik-full-data.md)沿用已批准的官方代码路线。[输入组件](../egoemg_repro/native_ik_inputs.py)仅只读原始文件，核验完整双手姿态哈希和所有数值，保留原默认六个连续分区、每批10096和最后不足一批的样本；原标签与manifest保持不变。后续即使在较少GPU上串行调度，也保留这六个逻辑分区的批次成员，避免改变L-BFGS的批内归约和停止行为。

官方`batch_ik_mesh.py`与遮挡渲染入口的设置不同：IK对双手均用right MANO、`flat_hand_mean=True`、内部β=0，先将姿态前三个全局旋转值清零，再执行原X翻转、固定对齐及旋转/平移优化。此处不套用遮挡渲染的实际β或左手镜像规则，不宣称已解决legacy左手约定差异。输出为20指角，不能代替FE/RU腕角重生成或缺失的markers2mano标注模型。

实际源每手66,161,725行、48个float32姿态值、12,703,051,200bytes。两个实际源目录均未发现原脚本可选的`valid.npy`；输入层保留所有零姿态，不用marker-valid或label-valid替换该文件。若该可选文件后来出现，已准入对象会失效，不能静默改变采样人口。

[40项新增真实文件工程检查](../results/native-mano-ik/input-engineering-tests-20261101.json)全部通过、无跳过。测试用53行明确工程数据，与原始`AnchorPoseDataset.__init__`源码逐分区核对完整行号，并验证原始/清零副本互不共享、RNG和原文件不变、九项属性变更及两处准入竞态会拒绝、伪造参考不能获得全量身份。组件导入不加载Torch，不构造几何模型或优化器。
