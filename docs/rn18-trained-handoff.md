# RN18融合的完整训练分支交接

这一步读取真实生产者，而不重新训练网络。原生融合需要完整历史RN18的 **LAST**，以及本折cotrain-S的 **验证BEST**。对应源码为[rn18_fusion_trained_handoff.py](../egoemg_repro/rn18_fusion_trained_handoff.py)，入口也从[rn18_fusion_handoff.py](../egoemg_repro/rn18_fusion_handoff.py)导出。

视觉来源继续使用已完成的[历史LAST独立准入](native-rn18-fusion.md)。其稳定读取器没有修改；不能换成新7,790点RN18的权重，因为训练足迹与未来融合留出区重叠。

EMG来源通过`read_rn18_fusion_emg_best`重读固定留出区cotrain生产者：

- 原训练历史、模型／AdamW／调度器／回调／循环／RNG保存状态、真实验证选优和完整110张量导出。
- 训练源码与记录的全部输入提供者逐文件匹配；明确提供来源目录，不执行任意目录中的Python代码。
- 重新构建完整可能随机训练足迹，确认与未来验证区间及测试输入零重叠；未来分区哈希必须一致。
- 两手实际EMG、共同元数据和标签逐项匹配当前已准入输入；生产者额外消费的腕部有效性／手势字段也检查实际文件哈希。
- 进程内注册对象绑定文件、来源路径、数据对象及来源摘要；复制对象、修改路径、改写导出或重封scope均不能获得完整许可。

`admit_rn18_fusion_initializers`只在完整注册队列、原cotrain150轮／36,150更新及验证BEST均通过后，生成两分支交接清单；`read_rn18_fusion_initializers`在新进程重新读取两边生产者和导出。运行时另外保存具体初始化身份摘要，完整分支来源与工程分支分开；模型构造本身不产生论文成绩。

当前工程验收使用真实CPU前缀→恢复的2轮／4更新生产者及小型实际memmap/crop输入。它可以证明读取、状态、来源绑定和拒绝路径，**不能证明完整150轮生产者、正式联合交接或融合实验已完成**。服务器正在运行的完整生产者，在尚无完成记录时也被实际拒绝。

完整训练生产者的正向联合交接、原生融合训练／恢复／完整验证测试及正式GPU资格仍待实际执行。既有legacy融合和ViT融合报告保持原身份，不由本工程验收覆盖。

[实际源码与CPU验收证据](../results/native-rn18-trained-handoff-engineering-20261102.json)：当前34项相关检查通过，0跳过（19运行时／15交接），包含真实前缀恢复、110张量和空缓存独立预测重放。17条警告来自原Transformer实现。最终套件复用同一已完成工程生产者，未重复训练；这些不是完整训练生产者正向准入。
